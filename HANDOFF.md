## 3. Key decisions and reasons
- Offline mode: provider "Ollama (offline)" plus a Setup switch "Always work offline" that overrides both provider menus, forces the Piper voice and sets `HF_HUB_OFFLINE` for Whisper. It means local AI and voice, not "no internet": Upload is not blocked (user request).
- Ollama is a system app like Git/Node, not studio-owned: its models live in the real user profile, so the server is started with the real environment, not the studio's.
- Offline animation runs the Claude Code CLI against Ollama's Anthropic-compatible endpoint (`claude_env` in `app/ollama_provider.py`), so the same skill and tools are used and no Claude login is needed. The model is copied once with a 64k context (`agent_model`), because Ollama's default window is too small and that endpoint cannot set it per request.
- Default offline model `gpt-oss:20b` (14 GB) was picked because it fits the 16 GB GPU, not from a quality comparison.
- Voice: Piper is the default engine (user request); "Free (Edge)" stays selectable on the Voice page. Settings saved before Piper existed always said Edge, so that value only counts as a choice once the `piper_default` setting exists. Offline mode forces Piper without changing the saved engine.
- Piper: `piper-tts` (pip, GPL-3) runs inside the studio's Python. Voices are `.onnx` files in `.cache/piper`, downloaded by the installer, by Setup's install, or on first use. Default `en_US-ryan-high` (120 MB); setting `piper_voice`. About 30 s of speech per 8 s on this CPU. The Windows SAPI voice was removed (too robotic).
- Gemini API is an **additional** provider, not a replacement. A rewrite that replaced `ai_providers.py` broke the GUI calls, the provider menu, Codex and the tests, so the CLI providers were restored.
- Animation with Gemini API goes through the Gemini CLI, because a plain API call cannot write files or run the render kit. It uses its own config folder (`.runtime/home/gemini-api-key`, see `gemini_key_home`) that selects key sign-in, because the CLI's normal folder keeps a Google login once chosen and ignores the key.
- Google now rejects the Google-account login in the Gemini CLI (`IneligibleTierError`, "migrate to Antigravity"), so the plain "Gemini" provider no longer works for this account. The error message points the user to "Gemini API".
- The studio `.env` wins over inherited Windows variables, and a `GEMINI_MODEL` that is not a model name is dropped. The Gemini key is sent in the `x-goog-api-key` header, never in the URL. `.env` is gitignored.
- A Gemini API request that waits the full 600 s fails at once instead of retrying; retries apply only to 429/500/503 and connection errors.
- No persistent Windows environment variables. Python 3.12 in the local `.venv`; reuse system Git/Node/FFmpeg/browser.
- All generated content is English. Edge voice default `en-US-AndrewMultilingualNeural`.
- Canvas + three.js in Chrome/Edge + FFmpeg, not Remotion. Video frames are JPEG; inspected stills/sheets stay PNG. Encoder probe: NVENC → QSV → AMF → CPU.
- Codex always stays sandboxed; the Full auto checkbox applies to Claude and Gemini only.
- License (user request 2026-11-11): GPL version 3, `LICENSE` at the root, for the studio's own code. The GrowKaz plugin and the niche-prompt PDF are third-party: they were untracked and gitignored on 2026-11-11 (user request) but stay on disk in both folders, where the installer and `install_local_skills` still need the plugin. On 2026-11-11 (user request) `main` was rewritten with `git filter-branch` to drop both files from every commit and force-pushed, and all 25 merged remote branches were deleted, so every commit ID from before that date changed and old SHAs in notes or PR pages no longer match `main`. GitHub still serves the old commits through the PR pages and direct commit links until GitHub Support purges them (the user has to ask). A local-only ref `refs/codex/turn-diffs/...` (Codex app data) still holds the two blobs; it is not on GitHub. `app/skills/scriptforge/SKILL.md` is derived from that PDF and is still tracked.
- Workflow the user follows: each change goes on a branch and a PR; merge only after they say so. They test by checking the branch out in the studio folder.
- OpenArt is animation-only (`TEXT_PROVIDERS` excludes it). The integration uses the official OAuth CLI from `.tools` with the studio ENV; login is scoped to `.runtime/home/.openart`. Requests use `--json` and `-o <folder>`. The vendor `install.ps1` is not used because it edits the user's PATH. A text provider writes the image/motion prompts from estimated narration positions; no Whisper alignment is used in this path.
- OpenArt settings live in `settings.json`, not persistent Windows variables. Effective defaults are shared by manual generation and Auto:

  | Setting | Default/effect |
  |---|---|
  | `openart_save_credits` | True for new and existing installations unless explicitly disabled; stills-only, 1080p, continuous local zoom/pan and short scene dissolves. |
  | Effective saving-mode timing | 12 seconds/image for long videos; 6 seconds/image for Shorts. Compatible saved plans retain their previous seconds/motion. |
  | `openart_parallel_shots` | 3, bounded 1–4; 1 is sequential. |
  | `openart_clip_seconds` | Custom-mode fallback 6, bounded 3–20; overridden at runtime in saving mode. |
  | `openart_motion` | Custom-mode fallback true; overridden to false for new saving-mode plans. |
  | `openart_image_model` / `openart_video_model` | `nano-banana-2` / `kling-3-omni` when blank; stage Model box is ignored. Video model is unused for new saving-mode plans. |

- Shot count is capped at 150; equal slices cover the complete voiceover and can exceed the target seconds for very long narration. In clip mode, requested shot timing is not passed as model clip duration: FFmpeg trims or slows each returned clip to fit, including transition handles. Local shot rendering uses CPU x264; GrowKaz's GPU encoder selection does not apply to this separate path. Landscape saving output is 1920×1080; vertical is 1080×1920, at 24 fps.
- Optional-flag recovery drops recognized rejected flags/fields (`--aspect-ratio`, `--resolution`, `--duration`, `--timeout`) individually and retries; it can retry several times when several different fields are rejected. Other errors propagate. Kling Omni pixel-to-tier mapping is model-specific; do not apply it blindly to other models.
- Resume: images/clips and `plan.json` live under `work/<slug>/openart/`. The normal key covers voice filename, duration, shot length, aspect and motion, not model, prompt text, image bytes, output resolution or concurrency. With saving mode enabled, `build_options` honors a compatible existing plan to retain paid assets. With saving mode off, custom timing/motion choices apply normally and an incompatible plan can clear/rebuild the folder. Use a new project for intentionally changed content; changing concurrency alone does not invalidate media.
- Cost intent: the user has **12,000 OpenArt credits/month** and wants multiple YouTube videos. An 8-minute new saving-mode build uses about 40 images and no clips, compared with 80 images plus 80 clips at 6 seconds previously. This is an asset-count comparison, not a confirmed credit quote. There is no budget cap, per-model cost estimator, selective per-scene AI-motion mode or automatic repurposing to Shorts. Parallelism saves time only. Retention guidance improves the creative brief; it does not guarantee viral videos. Paid generation is not needed for documentation/tests.
- OpenArt requires internet; turn off Always work offline. Generated music by mood, burned-in captions and interactive-agent mode are unavailable. Own music or no music is supported. Suggest character styles generates four paid OpenArt stills and is optional, not an Auto step. There is no GrowKaz visual-QC checkpoint loop in the shots path.

## 4. Failed approaches — do not repeat
- Replacing `ai_providers.py` with a Gemini-only module (different `run_agent`/`portable_prompt` signatures, lowercase provider names).
- `GEMINI_CLI_SYSTEM_SETTINGS_PATH` to force key sign-in: the CLI skips it ("parent directory is insecure").
- Whole-script Edge speech requests truncate or fail; use sentence-based passages with cache and retries.
- Sending `1080p` directly as Kling Omni resolution fails; use its `pro` tier. The CLI's `resolution: Invalid option` does not contain the leading `--`; recovery must recognize the field name.
- Sharing a single `self.proc` across concurrent OpenArt requests mixes process/output tracking and breaks Stop. Keep `CommandGroup`'s per-process handles and isolated output.
- Changing saving defaults must not silently discard a compatible paid shot plan. Do not promise that an old resumed clip-based project will become image-only.
- Bundled Playwright Chromium hung under antivirus; use installed Chrome/Edge. Python 3.15 broke faster-whisper/PyAV.
- Render errors left Chrome alive ~7 min (patch now exits). Deleting an output folder that is a shell cwd gives EPERM; empty it instead.
- Reusing an old slug overwrote earlier media. YouTube refresh with app-requested scopes gave `invalid_scope`; load the saved granted scopes.
- Codex `workspace-write` alone gave read-only sessions in the non-Git folder; explicit trust + Windows sandbox fixed it.
- Whisper/PyAV direct decoding failed with `metadata_errors`; decode PCM through FFmpeg first.
- Spawning `claude` with `--dangerously-skip-permissions` for a test is refused by the session's safety check; a test limited to `--allowedTools Write` in a temp folder is allowed.
